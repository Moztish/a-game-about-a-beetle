# Учебная система DAC/ACL на Java и SQLite

Консольное Java-приложение для демонстрации дискреционного управления доступом
(DAC), ACL, ядра безопасности и аудита. Оно находится отдельно от существующего
сайта регистрации: исходный Node.js-сервер и веб-страницы не меняются.

## Требования

- JDK 17 или новее
- Maven 3.8+
- Интернет при первом запуске Maven для загрузки SQLite JDBC и JUnit

## Сборка, тесты и запуск

Откройте PowerShell в каталоге `Myproject`:

```powershell
mvn test
mvn -q exec:java -Dexec.args="--bootstrap-admin"
```

Введите имя и пароль первого администратора (не менее 8 символов). Затем
запустите приложение без параметров:

```powershell
mvn -q exec:java
```

Зарегистрируйте обычных пользователей, затем войдите администратором или
пользователем. Пароли при вводе скрыты в терминале с поддержкой Java `Console`.
В терминалах без `Console` приложение предупреждает, что ввод пароля будет виден.

SQLite-база по умолчанию создаётся в `data/dac.sqlite3`. Можно выбрать другую:

```powershell
mvn -q exec:java -Dexec.args="--db .\data\class-demo.sqlite3"
mvn -q exec:java -Dexec.args="--db .\data\class-demo.sqlite3 --bootstrap-admin"
```

## Функции и модель доступа

- Регистрация обычных пользователей, аутентификация и однократное создание
  первого администратора. Пароли хранятся как PBKDF2-HMAC-SHA256 хеши с
  индивидуальной случайной солью.
- Создатель объекта становится его владельцем и получает `READ`, `WRITE`,
  `DELETE`. Владелец управляет ACL; администратор может читать, изменять,
  удалять все объекты и просматривать матрицу доступа.
- Владелец может независимо выдать или отозвать права `READ`, `WRITE`, `DELETE`
  другому пользователю. Пользователь без соответствующей записи ACL доступа
  не получает.
- `SecurityKernel` заново читает актуальную роль и ACL из SQLite в транзакции
  каждой операции. Решение клиента или ранее проверенное право не используются.
- Матрица ACL доступна владельцу объекта и администратору. Отказы записываются
  в журнал аудита.
- Режимы аудита: `ALL` (все события, по умолчанию), `SECURITY` (события
  безопасности и отказы) и `OFF` (аудит выключен). Менять режим и читать журнал
  может только администратор.
- Безопасная демонстрация «трояна» проверяет, смогло бы чтение пройти ACL, и
  записывает результат в аудит. Демонстрация не получает и не раскрывает
  содержимое объекта, не запускает процессы, не обращается к сети и не меняет файлы.

## Демонстрационный сценарий

1. Зарегистрируйте Alice и Bob, войдите как Alice и создайте объект.
2. Выйдите и войдите как Bob. Получите ID объекта из списка доступных объектов
   (до выдачи ACL чужой объект не появится) или заранее запишите ID.
3. Попробуйте прочитать объект и запустите симуляцию трояна: чтение будет
   отклонено, а попытка появится в аудите.
4. Войдите как Alice, выдайте Bob право `READ`; войдите как Bob и повторите чтение.
5. Отзовите `READ` у Bob и повторите чтение, чтобы проверить немедленное
   применение изменений ACL.
6. Войдите администратором и просмотрите журнал и матрицу ACL.

В меню для чтения и других операций можно вручную ввести ID объекта. Матрицу
можно просмотреть по ID, если он известен.

## Тестовые сценарии

```powershell
mvn test
```

JUnit-тесты используют изолированную SQLite in-memory базу и покрывают:

- регистрацию, вход, уникальность имени и однократное создание администратора;
- операции владельца `READ / WRITE / DELETE`;
- выдачу и отзыв независимых прав ACL, немедленное применение отзыва;
- обход ACL администратором и запрет обычному пользователю на просмотр аудита
  или смену режима;
- режимы `ALL`, `SECURITY`, `OFF`;
- аудит отказа и безопасную симуляцию «трояна» без доступа к содержимому;
- отсутствие частично созданных объектов при конфликте имени.

## Архитектура и схема БД

- `DacStore` — соединение SQLite, схема, аутентификация и аудит.
- `SecurityKernel` — проверки доступа и операции с объектами/ACL.
- `Session`, `Role`, `Permission`, `AuditMode` — модель субъектов и прав.
- `Main` — консольный интерфейс.
- Таблицы `users`, `objects`, `acl`, `audit_log`, `settings`.
- ACL представлена строками `(object_id, user_id, permission)`, по одной на
  каждое разрешённое действие пользователя над объектом.

## Основа для отчёта

В отчёте можно описать цель и модель угроз, DAC и матрицу
«субъект–объект–право», разделение приложения на хранилище и ядро безопасности,
схему БД и проверку ACL перед каждой операцией. В экспериментальной части
сравните результат чтения до выдачи права `READ`, после выдачи и после отзыва;
покажите записи аудита в режимах `ALL` и `SECURITY`. Зафиксируйте, что
симуляция трояна проверяет только решение ядра и не читает данные.

Это учебная основа, а не промышленная система: не реализованы сетевые сессии,
ограничение частоты входа, восстановление пароля и изолированное хранилище
аудита.
