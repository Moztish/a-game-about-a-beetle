# Лабораторная работа: DAC/ACL и модель Белла–ЛаПадулы

Учебное Java-приложение с графическим интерфейсом Swing и хранилищем SQLite.
Оно запускается отдельно от исходного Node.js-сайта в этом репозитории.

## Требования и запуск

- JDK 17 или новее;
- Maven 3.8 или новее;
- подключение к интернету при первой сборке Maven для загрузки JDBC/JUnit.

Из PowerShell откройте папку проекта `Myproject`:

```powershell
mvn test
mvn -q exec:java
```

При первом запуске приложение предложит создать администратора через окно.
Его допуск — `TOP_SECRET`. После создания можно регистрировать обычные учётные
записи на вкладке «Регистрация». Новым пользователям назначается
`UNCLASSIFIED`; администратор меняет допуск на вкладке пользователей.

Создать первого администратора без графического интерфейса можно в настоящем
терминале с доступным `System.console()`:

```powershell
mvn -q exec:java -Dexec.args="--bootstrap-admin"
```

### Демонстрационные данные

Для автоматической настройки демонстрации запустите приложение с отдельной,
пустой базой:

```powershell
mvn -q exec:java '-Dexec.args=--db data/demo.sqlite --seed-demo'
```

В приложении будут созданы аккаунты:

| Пользователь | Пароль | Роль | Допуск |
|---|---|---|---|
| `admin` | `AdminDemo123!` | ADMIN | TOP_SECRET |
| `alice` | `AliceDemo123!` | USER | CONFIDENTIAL |
| `bob` | `BobDemo123!` | USER | UNCLASSIFIED |
| `carol` | `CarolDemo123!` | USER | SECRET |

Это **публичные учебные пароли**: используйте только локальную тестовую базу,
не переносите эти учётные записи в production. Команда `--seed-demo` откажется
изменять базу, в которой уже есть пользователи. При необходимости укажите новый
путь после `--db`.

База по умолчанию — `data/dac.sqlite3`. Параметр `--db` задаёт другое имя файла.

## Как устроено управление доступом

Система объединяет две модели:

1. **DAC/ACL** — владелец управляет разрешениями `READ`, `WRITE`, `DELETE`;
   право может быть независимо выдано или отозвано для каждого субъекта.
2. **MAC Белла–ЛаПадулы** — обязательная проверка допуска субъекта и
   классификации объекта, которую ACL не может обойти.

Уровни расположены по возрастанию:

`UNCLASSIFIED < CONFIDENTIAL < SECRET < TOP_SECRET`

- **Simple Security Property («No Read Up»):** чтение разрешено, только если
  `уровень допуска субъекта >= классификации объекта`.
- ***-Property («No Write Down»):** запись и создание объекта разрешены, только
  если `уровень допуска субъекта <= классификации объекта`.
- Для `DELETE` применяются DAC-права владельца/ACL и административная роль.
  В данной модели Bell–LaPadula ограничивает конфиденциальность чтения и записи.
- Администратор имеет полномочия DAC и может назначать допуски, смотреть ACL,
  пользователей и аудит, но также подчиняется MAC-проверке `READ/WRITE`.
  Это отделяет административное управление от доступа субъекта к информации.
- Текущие роль и допуск, а также ACL перечитываются SecurityKernel из SQLite
  непосредственно при каждой операции.

## Интерфейс

- **Вход / Регистрация:** создание пользователей и аутентификация.
- **Объекты и ACL:** список видимых объектов, создание с классификацией,
  чтение, запись, удаление, выдача/отзыв отдельного права и просмотр ACL.
- **Монитор процессов:** очередь учебных фоновых запросов на чтение.
- **Аудит:** журнал событий и режим `ALL`, `SECURITY` или `OFF`.
- **Пользователи и допуски:** доступно только администратору.

## Безопасная демонстрация вредоносного процесса

Выберите объект на вкладке «Объекты и ACL», затем откройте «Монитор процессов»:

1. «Обычный процесс: READ» выполняет штатный запрос на чтение через SecurityKernel.
2. «Симуляция вредоносного процесса» проверяет, сможет ли имитируемый процесс
   прочитать выбранный объект. Ядро применяет ACL и `No Read Up`, результат
   сохраняется в аудит.

Второй сценарий **не читает содержимое объекта** даже при разрешённом доступе;
он лишь проверяет право и возвращает `WOULD_ALLOW` или `DENIED`. Монитор
наблюдает только учебные задачи внутри приложения: он не сканирует ОС,
не запускает исполняемые файлы или shell-команды, не изменяет файлы и не
выполняет сетевые действия.

## Аудит

- `ALL` — журналируются успешные операции и отказы (режим по умолчанию).
- `SECURITY` — журналируются события безопасности, изменения ACL/допусков и
  отказы. Обычные успешные `READ/WRITE` в этот режим не попадают.
- `OFF` — запись журнала отключена.

Менять режим и просматривать журнал может только администратор. Каждая запись
содержит время, субъекта, операцию, цель, результат и пояснение.

## Сборка и тесты

```powershell
mvn clean test
```

Тесты используют отдельную in-memory SQLite-базу и проверяют регистрацию и вход,
ACL, CRUD, административные ограничения, уровни Bell–LaPadula, режимы аудита,
безопасную симуляцию вредоносного процесса и набор демонстрационных данных.

Отчёт для сдачи лабораторной работы: [report/LAB_REPORT.md](./report/LAB_REPORT.md).

## Структура приложения

- `Main` — Swing-интерфейс, окна входа/регистрации, таблицы и действия пользователя.
- `SecurityKernel` — контрольная точка доступа: DAC/ACL и обязательные BLP-проверки.
- `DacStore` — SQLite-схема, миграция добавленных меток, учётные записи и аудит.
- `SecurityLevel`, `Permission`, `Role`, `AuditMode`, `Session` — модель предметной области.
- `ProcessMonitor` — безопасная очередь учебных процессов.
- `DemoData` — создание изолированного набора тестовых пользователей и документов.
- Таблицы SQLite: `users`, `objects`, `acl`, `audit_log`, `settings`.

Пароли хранятся как PBKDF2-HMAC-SHA256 хеши с индивидуальной случайной солью.
Приложение предназначено для учебного эксперимента, не является промышленной
системой защиты и не предоставляет сетевую аутентификацию.
